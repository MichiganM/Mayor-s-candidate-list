# MayorElection

Курсовой проект: программа формирования списка кандидатов на выборах мэра.

## Состояние

Версия 1.0.0: реализованы Domain, Data, бизнес-сервисы и рабочие WinForms-формы.
Репозиторий: [MichiganM/Mayor-s-candidate-list](https://github.com/MichiganM/Mayor-s-candidate-list).

## Требования и запуск

Windows, .NET 8 SDK, доступ к NuGet для восстановления зависимостей.
Выбран .NET 8 согласно требованиям задания; поддержка этой версии завершилась 10 ноября 2026 года.
Для промышленного использования требуется переход на поддерживаемую версию.

```powershell
dotnet restore MayorElection.sln
dotnet build MayorElection.sln --no-restore
dotnet test MayorElection.sln --no-build
dotnet run --project src/MayorElection.WinForms
```

Если SDK установлен локально, используйте `.tools/dotnet/dotnet.exe` вместо `dotnet`.
При запуске открывается форма входа; после полного успешного входа — список кандидатов.
При запуске применяются миграции. В пустой БД создаётся пользователь `admin` с ролью `Admin`.
Случайный пароль выводится в отдельную консоль только при создании; сохраните его.
Пароль не записывается в файлы или логи. Identity PasswordHasher настроен на 210 000 итераций,
блокировка — 5 неудачных попыток на 15 минут. AuthService учитывает ошибки пароля и TOTP.
При выходе открывается форма входа с новым DI scope, без предыдущей сессии и состояния EF.

## Работа в приложении

1. Войдите под `admin` с паролем из консоли первого запуска или зарегистрируйте нового пользователя.
2. Для подключения аутентификатора выберите «Настроить 2FA», подтвердите текущий пароль,
   получите QR-код, отсканируйте его приложением TOTP и введите шестизначный код.
   Секретный ключ доступен для ручного ввода. До подтверждения кода 2FA не включается.
3. Нажмите «Добавить», выберите шаблон и заполните данные. Для партийного кандидата укажите партию.
   Пустое отчество допускается. Даты выбираются через DateTimePicker.
4. Для редактирования выберите строку и нажмите «Изменить» либо дважды щёлкните строку.
   Статус можно изменить в редакторе или отдельным выпадающим списком и кнопкой «Сменить статус».
5. Фильтры над таблицей работают по статусу и шаблону совместно.
   «Вверх»/«Вниз» перемещают запись в полном списке, включая скрытые фильтром строки.
6. «Сохранить JSON» экспортирует полный список независимо от фильтра.
   «Загрузить JSON» запрашивает подтверждение полной замены списка.
7. «Выйти» завершает сессию. При включённой 2FA следующий вход потребует пароль и код.

Во время асинхронной операции форма блокирует повторные нажатия.
Ошибки валидации показываются рядом с полями и в сообщении; неожиданные ошибки записываются
в `%LOCALAPPDATA%/MayorElection/logs`. Формы выполняют привязку данных и вызовы сервисов,
бизнес-правила остаются в Services. ElectionApplicationContext отвечает за переключение окон.

## Миграции

Выполнять из корня репозитория:

```powershell
dotnet tool restore
dotnet ef database update --project src/MayorElection.Data --startup-project src/MayorElection.Data
dotnet ef migrations add <Name> --project src/MayorElection.Data --startup-project src/MayorElection.Data
```

Design-time factory ищет `src/MayorElection.WinForms/appsettings.json` вверх от текущего каталога.
Другой файл можно передать после `-- --settings <absolute-path>`.
Относительный путь SQLite разрешается относительно текущего рабочего каталога процесса;
для постоянного расположения задайте абсолютный `Data Source` в своей конфигурации.
Команда `database update` создаёт схему и справочник статусов; администратор создаётся при запуске приложения.

Иерархия Participant хранится по TPH. Номер кандидата уникален и положителен;
ссылочная целостность статусов и обязательность партийных данных защищены ограничениями SQLite.
Изменяемые сущности загружаются GetByIdAsync с tracking, списки — без tracking.
Repository не выполняет SaveChanges: сохранением и транзакциями управляет UnitOfWork.

## Бизнес-сервисы

`AddElectionServices()` регистрирует сервисы, FluentValidation и UserSession в DI.
Один desktop-сеанс использует один DI scope; вызовы сервисов в нём должны выполняться последовательно,
так как EF DbContext не поддерживает параллельную работу.

- AuthService: RegisterAsync, LoginAsync, Verify2FAAsync, Begin2FASetupAsync, Enable2FAAsync, Logout.
  Регистрация не выполняет автоматический вход. Подтверждение пароля проверяется DataAnnotations,
  правила пароля — Identity. После успешного пароля при включённой 2FA возвращается RequiresTwoFactor;
  сессия создаётся только после TOTP. Запрос второго фактора хранится в памяти 5 минут.
  Счётчик ошибок сбрасывается только при полном успешном входе. Для получения ключа настройки
  аутентификатора требуется текущий пароль. Setup возвращает ключ и otpauth URI для QR-кода в UI.
  Ключи, пароли, QR URI и TOTP не записываются в логи.
- CandidateService: ListAsync/GetAsync/AddAsync/UpdateAsync/ChangeStatusAsync/DeleteAsync.
  ФИО и даты проверяются DataAnnotations + FluentValidation; партийный шаблон требует название партии,
  самовыдвиженец не содержит партии. Статус проверяется по enum. Тип существующего кандидата
  фиксирован: для смены шаблона создаётся новая запись. Id и Position при обычном редактировании
  не изменяются. Добавление помещает запись в конец списка, удаление уплотняет номера.
- ListOrderService.MoveAsync: перемещение вверх/вниз в полном списке, граница списка — без изменений.
  Перенумерация использует положительные временные номера внутри одной транзакции.
- ExportService.SaveJsonAsync/LoadJsonAsync: JSON версии 1, максимум 10 МБ и 10 000 записей.
  Сохранение сначала пишет временный файл в том же каталоге. Загрузка полностью заменяет список:
  все поля проверяются до записи; Id уникальны, позиции составляют 1..N. При ошибке записи транзакция
  восстанавливает прежний список. Участники комиссии при импорте не удаляются.

Операции с кандидатами и файлами требуют авторизованного UserSession. Публичные методы с
CancellationToken поддерживают отмену. Валидация возвращает FluentValidation.ValidationException,
ошибки входа — AuthResult, некорректные файлы — InvalidDataException.

## Архитектура

- Domain: сущности, enum и контракты репозиториев. Зависимость от Identity необходима для требуемого ApplicationUser : IdentityUser.
- Data → Domain: EF Core, SQLite, Identity store, репозитории и миграции.
- Services → Domain: бизнес-сервисы, DTO, валидация. Слой не зависит от EF Core или UI.
- WinForms → Services, Data: формы и composition root с DI.
- Tests → Services, Data: модульные и интеграционные проверки.

Маппинг DTO ручной: небольшой набор сущностей позволяет явно контролировать поля без дополнительной библиотеки.
Строка подключения задаётся в `appsettings.json`. Реальная БД и логи исключены из Git.

## Тесты и автономная сборка

Реализованы 6 модульных и 16 интеграционных тестов. Тесты проверяют валидацию, статусы,
порядок, PasswordHasher, TOTP, блокировки, миграции, JSON и откат транзакций.
В последнем локальном запуске — 22/22; покрытие строк Services — 97,58%.
Проверка NuGet (включая транзитивные зависимости) не обнаружила известных уязвимых пакетов.

```powershell
dotnet build MayorElection.sln -c Release
dotnet test MayorElection.sln -c Release --no-build --collect:"XPlat Code Coverage" --results-directory artifacts/TestResults
dotnet publish src/MayorElection.WinForms -c Release -r win-x64 --self-contained true -o artifacts/MayorElection-win-x64 -p:PublishTrimmed=false
```

После publish запустите `artifacts/MayorElection-win-x64/MayorElection.WinForms.exe`.
Для этой сборки не требуется установленный .NET или сервер БД. Переносить нужно весь каталог
с DLL, native SQLite и appsettings.json; запускать из каталога, доступного для записи.
В GitHub Actions доступны артефакт приложения и отчёты тестов после успешного workflow.
Сгенерированные артефакты, БД и логи в Git не включаются.

## Ограничения

Восстановление доступа при утрате аутентификатора и смена пароля в UI не реализованы.
Роль Admin создаётся при первом запуске; все зарегистрированные пользователи имеют одинаковый доступ к CRUD.
Полный ручной сценарий с внешним аутентификатором и файловыми диалогами ещё требует проверки.
Возрастные и иные юридические критерии допуска к выборам не задавались и не моделируются.
