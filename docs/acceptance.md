# Проверка перед защитой

## Автоматические проверки

В корне репозитория, Windows и SDK из global.json:

```powershell
dotnet restore MayorElection.sln -p:NuGetAuditMode=all -warnaserror
dotnet build MayorElection.sln -c Release --no-restore -warnaserror
dotnet test MayorElection.sln -c Release --no-build --collect:"XPlat Code Coverage" --results-directory artifacts/TestResults
dotnet tool restore
dotnet ef migrations has-pending-model-changes --project src/MayorElection.Data --startup-project src/MayorElection.Data --configuration Release --no-build
```

UnitTests проверяет валидацию до обращения к репозиторию, смену статуса,
порядок и состав списка, Identity PasswordHasher (включая соль), настоящий
Identity AuthenticatorTokenProvider и валидацию дат с управляемыми часами.
SQLite для этих шести тестов не используется.

ServiceTests и DataIntegrationTests (16 тестов) проверяют сервисы с настоящими
SQLite в памяти и ASP.NET Core Identity, миграции, роли, блокировки, сессию,
TOTP и истечение запроса второго фактора, ограничения и откат транзакций,
JSON round-trip и отказы импорта. Пользовательская БД не используется.

## Ручной сценарий

Следующие шаги предназначены для проверки на отдельной демонстрационной БД.
В отчётах этапов отдельно указано, какие проверки фактически выполнены.

1. Запустить приложение с новой БД. Убедиться, что открылась форма входа,
   а случайный пароль `admin` выведен только в консоль первого запуска.
2. Проверить регистрацию: несовпадающие пароли и слабый пароль отклоняются,
   корректная учётная запись создаётся; повторный логин отклоняется.
3. Войти, выйти, войти повторно. Убедиться, что старый пользователь не сохраняется в сессии.
4. Подключить аутентификатор по QR или вручную; неверный код не включает 2FA.
   После верного кода выйти: одного пароля теперь недостаточно.
5. На отдельном тестовом пользователе ввести неверный пароль пять раз:
   последующий правильный пароль отклоняется на 15 минут.
6. Добавить самовыдвиженца и партийного кандидата; проверить обязательность партии,
   ФИО без цифр, даты и пустое необязательное отчество.
7. Отредактировать данные, изменить статус, применить оба фильтра совместно.
8. Переместить записи вверх/вниз и проверить номера; удалить запись и проверить отсутствие пробелов.
9. Сохранить полный список JSON, изменить состав, загрузить сохранённый файл.
   Подтверждение импорта должно предупреждать о полной замене списка.
10. Загрузить испорченный JSON: текущий список должен остаться прежним.
11. Перезапустить приложение: пользователи, 2FA и кандидаты сохранены.

## Иллюстрации для пояснительной записки

Добавить собственные скриншоты: LoginForm, RegisterForm, TwoFactorSetupForm,
MainForm с двумя шаблонами и фильтрами, CandidateEditForm с ошибкой валидации.
На скриншоте 2FA закрыть QR и секретный ключ; использовать вымышленные персональные данные.
